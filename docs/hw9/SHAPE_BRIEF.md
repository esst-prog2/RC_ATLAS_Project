## Purpose and audience

Introduce RC Atlas as an institutional workspace connecting project management, monitoring, indicators, analytics, and reporting. Help a classmate, professor, or first-time visitor understand the platform and explore its public source. Intended product users include programme managers, field coordinators, and monitoring/evaluation teams. Visitor mode: Persuade.

Explain configured indicator analysis and report previews accurately. Keep limitations beside the relevant claims, using plain language instead of technical exception lists.

Use the source-grounded copy in CONTENT_REVIEW.md. No customer logos, testimonials, impact statistics, deployment claims, or invented interface images. Genuine screenshots may be included only after synthetic-data and provenance verification; their exact selection is still open.

## Page sequence

1. **Identity and purpose.** RC Atlas name, approved headline, short explanation, visible Explore on GitHub action, and See the workflow link.
2. **The institutional problem.** Responsibilities, progress, evidence, and review must be understood together; task completion alone does not measure impact.
3. **Five connected capabilities.** Project management; monitoring; indicators; analytics; reporting. Each gets a brief, concrete explanation, not a claim of universal readiness.
4. **Accountability in practice.** Assign → Work → Submit → Validate → Approve. Role descriptions and, where safe, genuine UI evidence show the handoffs. Avoid implying task approval automatically updates an outcome indicator.
5. **Understand the result.** A concise explanation of configured indicators, calculation context, and explicit unavailable states. Reporting records and previews help people review available information; governed exports remain future work.
6. **Explore RC Atlas.** Public GitHub repository and local setup guide; clearly identify the application as locally run. Reserve this section's media area for the HW10 video; until then it contains useful workflow text or a verified still, never an empty player or a fictitious Play button.
7. **Footer.** Repository link, project/course context, and brief scope note. No invented contact details or commercial signup form.
